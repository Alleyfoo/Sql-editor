## What was completed this session

### Refactor: `st.navigation` → single-script `st.tabs` (complete)

Replaced the sidebar page selector with a top-of-page tabbed layout
(`streamlit_app.py` rewritten to use `st.tabs` instead of
`st.navigation`). Three panels, left-to-right:

- **Studio** — data + query app (the primary surface)
- **LLM SQL Assistant** — heuristic-vs-LLM showcase
- **Workflow** — four-step interactive guided tour

The tour walks the user through: (1) load the demo dataset, (2) try
the heuristic on Studio, (3) compare with the LLM, (4) hand the LLM
plan back to the Studio. Each tour step is a one-click button that
pre-fills the relevant input and switches to the right tab — no
explicit back navigation, the tabs themselves are the way back.

#### Why a single script (not just `st.navigation` with new pages)

The old setup used `st.navigation` to switch between Studio and LLM
Assistant via a sidebar picker. Three problems:

1. The sidebar picker was a sidebar widget — not where users look
   first, and it took up real estate.
2. No obvious entry point — users opened the app and landed wherever
   the last session put them.
3. No explainer of the Studio ↔ LLM round-trip workflow — the
   relationship was implicit.

The new tabbed layout fixes all three and adds the guided tour as a
first-class panel. `st.tabs` with a bound `key=` keeps the active
tab in `st.session_state["main_tabs"]`, so cross-tab handoff is a
session_state write, not a `st.switch_page` call (which doesn't work
under tabs).

#### Visible order vs body order — the chip-prefill trick

The `st.tabs` widget renders labels in the order they appear in the
constructor argument (Studio, LLM, Workflow — visible left-to-right).
But the body `with` blocks run in script order. The Workflow tab's
buttons write private prefill keys (`_llm_showcase_chip_prefill`,
`nl_prefill`), and the LLM tab's `render()` pops those keys *before*
its widgets are instantiated. So the script body order is deliberately:

```
with tab_studio:    studio.render()      # 1st
with tab_workflow:  workflow.render()    # 2nd (writes prefill keys)
with tab_llm:       llm_assistant.render() # 3rd (pops prefill keys)
```

By running the LLM tab body *after* the Workflow tab body in the
same top-to-bottom pass, the prefill is visible in the same rerun —
no extra `st.rerun()` needed for the chip-prefill pattern to work
cross-tab. The visible order is decoupled from the script order;
only the script order matters for the trick.

#### Tab label constants — single source of truth

The three tab label strings are defined once in
`src/streamlit_app/__init__.py`:

```python
TAB_STUDIO = "Studio"
TAB_LLM = "LLM SQL Assistant"
TAB_WORKFLOW = "Workflow"
```

Both the entry script and `_handoff` import from this module so a
typo in one place can't desync the cross-tab handoff.

#### Test-isolation gotcha worth knowing

AppTest runs the script in the same Python process as the test, so
`st.rerun = lambda: None` inside a script patches the **shared**
`streamlit.rerun` and silently breaks every subsequent test that
relies on rerun (e.g. the workflow button click). The two handoff
tests save `_original_rerun = st.rerun` and restore it in a
`finally:` block. This is documented in the test docstrings so the
next person doesn't get bitten.

### Fix: blank page body under `st.navigation` (complete)

**Bug:** opening the app showed the sidebar page selector but the page
body was blank on both Studio and LLM Assistant. The selector worked
because `st.navigation` ran in the entry script — the page body was
empty because the page modules defined `render()` but **never called
it at module level**.

**Why:** `st.navigation` runs a page by `exec`'ing its bytecode in a
fresh `__main__` module (see `streamlit/navigation/page.py:482`). The
official Streamlit `hello` template puts the page body at module top
level; our pages put it inside `def render():` and relied on the
(AppTest-only) call site to invoke it. Real `streamlit run` never
called `render()`.

**Fix (`src/streamlit_app/pages/studio.py` and `llm_assistant.py`):**
added a `if __name__ == "__main__": render()` guard at the bottom of
each page module. The guard fires when `page.run()` execs the module
as `__main__`, and is a no-op when tests or `app.py` import the page
under its dotted name (so the import stays side-effect-free).

**Regression test (`tests/test_llm_assistant_render.py`):**
`test_page_runs_render_when_execd_as_main` — compiles the page source
fresh from disk, execs it with `__name__ == "__main__"` inside an
AppTest session, and asserts that body elements were emitted. Verified
to fail without the fix (0 body elements — the exact "blank page"
symptom) and pass with the fix.

### Bug fixed during implementation

The first version of the page had the chip-click handler do
`st.session_state["llm_showcase_nl"] = example` *after* the text area
was instantiated. Streamlit raises an exception for that
(`cannot be modified after the widget is instantiated`). The test suite
caught it. Fix: chips set a `_llm_showcase_chip_prefill` key, and the
prefill is applied to the text-area session state key *before* the
widget is created. This is the same pattern the existing Studio Ask
component uses.
