**New page affordances (`src/streamlit_app/pages/llm_assistant.py`):**

| Feature | Where | Why |
|---------|-------|-----|
| **Status pill in LLM column** | next to the LLM header | mirrors the Studio's topbar pill — `● online / offline / retry` at a glance |
| **Row-count estimate** | both columns' success badges | shows what `▶ Run query` *will* return, e.g. `≈ 3 rows` for `sum revenue by region` |
| **Status badges** | heuristic + LLM | `✓ Parsed`, `✓ accepted`, `✗ rejected`, `↪ routed to Python` with latency next to them |
| **Raw LLM JSON plan** | "Model reply" expander on the LLM column | surfaces the verbatim JSON the model returned (post schema-repair retry) — the *only* way to audit what the model actually said |
| **Plan diff** | between the two columns | field-by-field `selected_columns`/`filters`/`group_by`/`order_by`/`limit` with `✓ agree / ≠ disagree / H heuristic-only / L LLM-only` marks |
| **Comparison log** | bottom expander | last 10 runs as `{ts, input, heuristic_sql, llm_status, llm_sql}` — pattern reused from parcel-ops `llm_saved_results.json` |
| **Schema-aware example chips** | top of input | chips generated from the loaded schema (e.g. "sum revenue by region") when it has ≥ 1 numeric + ≥ 1 text column; falls back to static chips for small schemas |
| **Copy-SQL on both columns** | above each `st.code` | free, via `st.code`'s built-in copy-on-hover icon — no hand-rolled HTML |
| **Unrecognized-token expander** | heuristic column | shows what the regex path couldn't match, so the user can see whether to fall back to LLM |
| **Latency** | LLM column | `~1.4 s` next to the status badge |
| **Use this plan** handoff | bottom of LLM column | deep-copies the chosen `QueryModel` into `st.session_state.model` / `.last_sql` and calls `st.switch_page` back to the Studio |

**New LLM API knob — `src/llm/natural_language.py`:**
- `nl_to_query_model(..., return_raw: bool = False)` — when `True`,
  returns `(model, raw_payload)` instead of just `model`. The payload
  is the literal JSON the model produced (post the schema-repair
  retry). Existing callers get a `QueryModel` unchanged.

**Architecture change — multipage app:**
- Converted the single-page app to a Streamlit `st.navigation` multipage
  app. The Studio body is byte-identical to the previous build, just
  moved to `src/streamlit_app/pages/studio.py`. `streamlit_app.py` now
  registers two pages and runs the selected one. The old
  `src/streamlit_app/app.py` is a thin re-export (`from .studio import
  render as run`) so any old import path still works.

**New page — `src/streamlit_app/pages/llm_assistant.py`:**
- Side-by-side **heuristic vs LLM** comparison, modelled on the
  parcel-ops regex vs LLM showcase pattern (`llm_classifier.py`).
- The heuristic column is free and runs eagerly on every keystroke.
  The LLM column shows a placeholder until the user clicks
  **▶ Run comparison**, then calls the *same* `nl_to_query_model`
  function the Studio's Ask button uses.
- Visible **safety banner** lists the six layers the README §"Safety
  guarantees" promises — answers the "is the LLM running my SQL?"
  question up front.
- Status badges: `✓ accepted`, `✗ LLM error`, `↪ routed to Python
  analytics`. Latency shown next to the badge.
- **"Use this plan" handoff** — two buttons (heuristic / LLM) write
  the chosen `QueryModel` into `st.session_state.model` /
  `st.session_state.last_sql` and call `st.switch_page` back to the
  Studio, where the SQL preview is already populated.
- Reuses (no new code): `heuristic_nl.parse_heuristic`,
  `llm.nl_to_query_model`, `llm.load_llm_config` + `make_llm_client`,
  `QueryModel.to_sql`, `demo_dataset.load_demo`, `styles.inject_css`.

### Bug fixed during implementation

The first version of the page had the chip-click handler do
`st.session_state["llm_showcase_nl"] = example` *after* the text area
was instantiated. Streamlit raises an exception for that
(`cannot be modified after the widget is instantiated`). The test suite
caught it. Fix: chips set a `_llm_showcase_chip_prefill` key, and the
prefill is applied to the text-area session state key *before* the
widget is created. This is the same pattern the existing Studio Ask
component uses.
