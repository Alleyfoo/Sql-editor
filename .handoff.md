# Handoff - 2026-07-06

## What was completed

### Tour: scroll-driven presentation as the app's front door (this session)

The user said the workshop's three-tab layout splattered the core idea across
pages and visitors had to assemble the point themselves. Replaced it with a
**Tour** — a scroll-driven presentation that tells the thesis as five live
beats against a tour-private demo connection, with the workshop reachable as a
secondary escape hatch.

Thesis (user-chosen): the whole flow as one story — ask → safe plan → approve →
run → auto-insight. Shape (user-chosen): guided scroll walkthrough, not a tabbed
workshop.

**New file `src/streamlit_app/pages/tour.py`** (~430 lines):
- `_ensure_tour_demo()` loads the bundled demo into **tour-private** session
  keys (`_tour_conn`/`_tour_schema`/`_tour_df`/`_tour_meta`), fully decoupled from
  the workshop's `ss.conn` so the narrative is deterministic regardless of what a
  visitor uploads in the workshop.
- `_render_bar()` — brand + one-line thesis + the **⚙ LLM popover** (reuses
  `header._render_model_selector`) so visitors paste a free Groq/Gemini key right
  on the tour (the point of the README work). No Open-CSV control here.
- `_render_hero()` — "Ask your CSV anything. Safely." + the safety callout.
- Five `_chapter()` cards (reuses `.wf-step*` CSS): ① data + editable question,
  ② why-safe contrast (BAD_SOFT vs GOOD_SOFT), ③ the plan (heuristic
  `parse_heuristic` → JSON breakdown; optional LLM button), ④ approve+run
  (`model.to_sql()` → `render_sql_block` → `▶ Run query` → `executor.execute` →
  `results._render_table`), ⑤ auto-insight (`compute_insights` → insight cards +
  self-contained chart; optional LLM narrative button).
- `_render_escape_hatch()` — "Open the full Studio / LLM tools →" writes
  `_pending_view="workshop"`, `_pending_main_tab=TAB_STUDIO`, `nl_prefill=question`,
  reruns. Lands the visitor in Studio with the tour question pre-filled.
- `_DEFAULT_QUESTION = "sum revenue by region"` (verified to parse via heuristic
  with SUM+GROUP BY; the earlier "monthly revenue trend 2024" did NOT parse —
  conf 0.0). `_EXAMPLE_QUESTIONS` all verified to parse.
- Reuses all existing pipeline callables — **no new pipeline code**.

**`streamlit_app.py`** — rewired to a `view` session key (default `"tour"`):
- `_pending_view` pending-flag apply block (mirrors the existing
  `_pending_main_tab` pattern) before the conditional.
- `view == "tour"` → `tour.render()` (no `st.tabs`, full-page).
- `view == "workshop"` → `st.tabs([TAB_STUDIO, TAB_LLM], key="main_tabs",
  on_change="rerun")` dispatching `studio.render()` and `llm_assistant.render()`.
  The standalone Workflow tab is dropped from dispatch (Tour supersedes it);
  `pages/workflow.py` kept on disk so its existing tests still pass. A
  "← Back to tour" button returns to the tour. (Note: the `←` U+2190 char
  required `encoding="utf-8"` in the sys_path test's `open()` + subprocess.)
- `_VALID_TABS = (TAB_STUDIO, TAB_LLM)`; a garbage/stale `main_tabs` resets to
  Studio.

**Tests** — `tests/test_tour_render.py` (10 new): module exposes render; renders
+ loads demo; five chapter cards render (filter on `'<div class="wf-step">'` to
exclude the inject_css `<style>` block); default question parses via heuristic;
all example chips parse; chapter-4 SQL panel renders passively; chip changes
question (pending-flag); Run executes+caches under `_tour_results[question]`;
escape hatch writes the three workshop-switch keys; passive render never calls
the LLM (patches `nl_to_query_model` to raise). `tests/test_llm_assistant_render.py`
— 4 tests updated for the view flag: default view is tour; workshop tabs render
in order [Studio, LLM]; escape hatch prefills Studio; invalid main_tabs falls
back to Studio. Used `AppTest.from_file()` + `at.session_state[k]=v` + `at.run()`
(the `from_string` + `import streamlit_app` form caches in `sys.modules` and
no-ops on the second test).

**Verification:** pytest **290/290 green**; Playwright DOM smoke **11/11 green**
(tour lands with no tab bar; hero present; five chapter titles; default question
populated; example chip present; LLM popover present; chapter-4 SQL shows
SELECT; ▶ Run query produces a results table; escape hatch switches to the
workshop tabs; Back-to-tour returns; no stException).

**Playwright timing lesson:** Streamlit streams elements over the websocket in
batches and hydrates widgets before markdown, so the bottom escape-hatch button
can appear while chapters 2–5's markdown is still hydrating. The reliable
"fully rendered" signal is `document.querySelectorAll('.wf-step').length >= 5`,
not the escape-hatch button. (Below-the-fold buttons still need
`element.evaluate(e => e.click())` because Playwright's auto-scroll targets the
window, not Streamlit's inner `stMain` container.)
